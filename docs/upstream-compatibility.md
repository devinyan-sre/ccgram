# 上游功能兼容审计（2026-09-02）

本项目以 [alexei-led/ccgram](https://github.com/alexei-led/ccgram) 为上游，但不直接整分支合并。本分支已经拥有持久化 Outbox、按话题隔离的队列、破坏性操作审计/熔断、Provider 就绪策略、自动挂起等独立能力；全量合并会覆盖这些生产安全语义。

## 已兼容

| 上游能力 | 本分支处理 |
| --- | --- |
| Telegram HTTP 客户端并发重置、合理的 getUpdates 读超时 | 已适配，并保留本分支 Bot API 指标和错误告警 |
| 每群话题探测预算、轮转与 RetryAfter 退避 | 已适配，同时保留“权威二次确认后才杀窗口”和群体死亡熔断 |
| Agent 退出后不误切换成 shell | 已适配；保留原 Provider，由现有就绪策略安全重启 |
| Provider 安全的列表恢复 | 已适配；只有能可靠扫描会话的 Provider 显示列表恢复，选中项携带 Provider |
| 转录截断/替换/重写/半写入稳定读取 | 已适配到持久化 Outbox，两游标投递确认语义保持不变 |
| Telegram 原生回复草稿 | 已适配；草稿仅作预览，最终消息仍经过 Outbox |
| Unicode 上传文件名、群组 WebApp 按钮抑制 | 已适配 |
| Herdr 输入与 Enter 分离、protocol 17/19/20 | 已适配 |
| 语音自动发送、隐藏状态气泡 | 已作为默认关闭的配置项适配 |
| v4.9.4 跨成员窗口绑定去重 | 已按本分支成员通道模型适配；默认窗口在全局只能归属一个“成员 + 话题”，启动时自动修复旧重复映射，显式任务通道仍按所有者校验 |
| v4.9.4 编号及 Yes/No 快捷按钮 | 已适配到所有可识别的 CLI 交互提示；仅为明确的单选菜单生成按钮，多选或歧义内容仍保留方向键；按钮绑定消息、话题、窗口和提示代次，过期/双击不会误投 |
| v4.9.3 持续输出的投递游标收敛 | 已适配到本分支持久化 Outbox；游标可推进到最早待投递批次的起点，忙碌会话不再必须等待整个队列变空，同时保持重启后至少一次投递语义 |
| v4.9.2 Telegram RetryAfter 隔离 | 已采用请求级重试、指数退避和抖动；一个受限请求不会建立全局反应式暂停，重试耗尽交回现有队列恢复逻辑 |
| v4.9.2 话题重命名节流 | 已按群设置 1.5 秒间隔及 5 分钟 flood cooldown；轮询更新延后到下一轮，`/sync` 在群级锁中等待，不阻塞普通回复 |

## 本轮审计范围

本轮对比本分支 `v4.6.7` 同步点与上游 `v4.9.4`（提交 `790ba49`），逐项审计约 34 个后续提交。采用的是行为级移植而非直接 cherry-pick：路由、投递、并发和安全边界继续以本分支实现为准，并为每项移植增加回归测试。

## 暂不纳入

| 上游能力 | 决策与原因 |
| --- | --- |
| 多群组全链路路由重构 | 当前生产实例由 `CCGRAM_GROUP_ID` 限定单群；上游改动横跨路由、状态与回调约 60 个文件，会与本分支按话题队列/Outbox 键冲突。保留为以后有真实多群需求时的独立迁移项目 |
| Google Antigravity (`agy`) Provider | 当前主机未安装 `agy`，无法做真实启动、恢复和转录验证；不发布未经端到端验证的 Provider |
| 整体替换上游话题清理逻辑 | 本分支的 close-by-default、权威 topic-gone 确认、审计与 mass-death breaker 更严格，继续保留 |
| 私聊话题支持 | 当前生产与成员并发架构以 Telegram Forum 群为边界；私聊没有相同的工作区/成员隔离需求，暂不扩大授权面 |
| `agterm`/Antigravity 相关集成 | 当前主机没有对应后端，无法做真实端到端验证 |
| “跳过积压直接追实时” | 会主动丢弃用户尚未看到的输出，与本分支 Outbox 不丢消息语义冲突，不纳入 |
| 整体替换上游批量发送 | 上游批处理没有本分支“回复到根问题、成员任务通道、Outbox 分段恢复”的全部关联信息；待能证明不破坏归属和重启恢复后再单独适配 |

后续同步采用同一门槛：功能需有当前使用价值、不会削弱本分支的持久投递/破坏保护、具备自动测试，并能在部署前通过健康检查。
